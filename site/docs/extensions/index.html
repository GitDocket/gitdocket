Keep the workflow with the project

An extension is a package of Markdown workflows, templates, guidance, and tool instructions. GitDocket installs it under docket/extensions/. Commit those files and your project choices so another checkout has the same process.

Ask your agent to use a named workflow, such as product-delivery:deliver. It reads the instructions, prepares the work, and brings the result back for review. You can choose the reviewer, change the checks, and adapt the templates.

Your proposals, decisions, and completed work stay in the project when you update or remove an extension. GitDocket manages package updates and flags conflicts with your edits.

Use the tools your agent already has

A workflow can use connected tools to read an issue, inspect checks, or prepare a handoff. It uses your agent’s existing connections and permissions. You decide when to send a handoff or publish a result.

The agent follows the workflow’s instructions and runs the checks. Review steps depend on those instructions being followed; installing an extension does not set up external services or enforce approvals automatically.

Install GitDocket with Homebrew or npm, then try the Beacon walkthrough. Its example app also needs Bun; the guide lists the setup steps.

GitDocket and its extensions are in preview. You can also start with one task and add a workflow later.
