# Website deployment

All public pages, including the 404 page, link from the primary navigation and footer to the [GitHub issue chooser](https://github.com/GitDocket/gitdocket/issues/new/choose) and [release notes](https://github.com/GitDocket/gitdocket/releases). The footer and setup-help points also offer [hello@gitdocket.com](mailto:hello@gitdocket.com), verified for receipt and replies in the maintainer’s Workspace inbox. Feedback is open to rough impressions as well as bug reports; GitHub sign-in is required, diagnostic details are optional, and public reports must omit private project content. Keep the getting-started and installation recovery points aligned with their source Markdown and CONTRIBUTING.md.

The site is static: no package install, build step or server runtime. It uses Cloudflare Web Analytics to measure website visits and page performance. Domain-level automatic setup injects one beacon from `https://static.cloudflareinsights.com`, with its integrity attribute, and reports to the same-origin `/cdn-cgi/rum` endpoint. Keep the Pages project's separate analytics integration disabled and do not add a second beacon to authored HTML. The content security policy permits local scripts and that Cloudflare script origin, with connections restricted to this site. See [Cloudflare's CSP guidance](https://developers.cloudflare.com/web-analytics/faq/).

Website analytics is separate from GitDocket's local CLI telemetry. CLI observations remain local and opt-in; the website beacon does not receive them or project repository content.

All HTML pages load one local script, `site/copy-install.js`, which adds a Copy button to every code block and powers the existing Homebrew controls. Each control copies only its associated code text, preserving indentation and line breaks, with keyboard access and success/failure feedback. Without JavaScript, code remains selectable and copy controls stay hidden. Keep the shared script on new pages so new code blocks receive the same behavior.

Use one compact code block and one Copy action per coherent activity. Related shell commands may share a block when they can run together without a decision or review pause; chain them with `&&` so a failed command prevents later commands in the sequence. Keep explanatory prose and separate blocks at choices, edits, long-running servers and review points. Explain prerequisites and replacement values before the relevant block. Keep a dry run separate from its apply step with a review instruction, and label optional or alternative operations individually. Keep each JSON document intact with `language-json` (Copy JSON), and mark MCP tool-name/argument examples `language-mcp` (Copy example) with an explanation that they belong in an MCP client. Shell examples use `language-sh`. Keep source Markdown and public HTML aligned when revising their instructions. The Copy control sits beside the code without a separate toolbar row; keep padding modest. All HTML pages use content-hash query strings for the shared CSS and script; refresh those hashes when either asset changes so returning browsers load matching versions.
