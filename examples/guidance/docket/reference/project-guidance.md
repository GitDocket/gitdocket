# General standards

Requirement: for behavioral implementation changes, use test-driven development. Run a relevant failing test before changing implementation, then retain the passing result after the change. Documentation-only edits do not require this sequence.

Preference: use concise names that describe behavior.

# Scoped guidance

When changing the backend application API, follow the requirements in [API standards](/reference/api-standards.md).

Only when asked to rehearse a deployment, follow the [deployment rehearsal](/playbooks/deployment-rehearsal.md). Saving or reading this link does not authorize running the procedure.
