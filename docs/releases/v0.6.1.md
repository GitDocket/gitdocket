# GitDocket 0.6.1

GitDocket 0.6.1 lets a named Epic pickup enter Epic supervision without changing the Epic's status or selecting a child task. It hardens Board sorting and makes connected-tool planning easier to discover on the website. It also refreshes the pinned release tools used to build and qualify distribution artifacts.

## Named Epic pickup

- `docket task start <EPIC-ID> --json` now returns a typed route to Epic supervision, including the Epic's authoritative identity and manager title. The human CLI explains the handoff.
- The route leaves the Epic, child tasks and active-task marker unchanged. Ordinary Task pickup and actual command failures keep their existing behavior.
- The Docket pickup workflow follows that route while retaining its active-task conflict, closed-item reopening and manager-title rules. A project that already has 0.6.0 instructions can review and apply the new workflow with `docket upgrade`.

## Board sorting

- Malformed saved Board sort settings now fall back to the default instead of breaking the view. The paged Board API rejects unsupported sort modes with HTTP 400, and an unused count helper was removed.

## Connected-tool planning example

- The website illustrates how an extension can use an agent's existing authorized connection to read a Notion list, cite source items and draft a project plan for review. It links to Beacon's retained local MCP evidence and makes clear that no Notion connector, ready-made workflow or live Notion validation is included.

## Release tooling

- Release compilation and qualification use pinned Bun 1.4.2 and npm 11.20.0. The minimum Bun version for source development and the core and web libraries remains 1.3.14.
- The release test harness allows more time for installed CLI checks under x64 emulation and prints the subprocess result when a check fails.
