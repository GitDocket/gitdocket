# GitDocket 0.6.4

## Highlights

- Explicit work inventory questions use complete filtered task lists directly, while overview remains the bounded orientation view. Agents reuse fetched results when only selecting fields or formatting an answer.
- Overview and epic-list reads batch committed task evidence through Git, reducing process overhead while preserving source freshness, inventory completeness and explicit incomplete-evidence reporting.
- The retained exact-search index uses compact numeric postings and unique word lists to reduce construction work and allocations while preserving ranking, snippets, complete link neighborhoods and older readers during edits.
- Pickup conflict handling checks applicable host, user, session and project authority before asking for worktree approval. Already-authorized isolation proceeds without another question; missing authority receives one concrete request with the recommended next action first.
- Workspace conflicts and overlapping edits are handled separately. Epic supervision continues independent ready work while affected edits wait for ownership or authorization, with clearer blocker messages.
- Epic review requests name the result and the action approval enables, reuse plain-language acceptance for the same scope, and keep required source explanations brief without repeating skill routing.
- The published 0.6.3 workflow bodies remain frozen as upgrade merge bases. Historical, customized and stale adopters receive the updated instructions or an explicit review requirement.
