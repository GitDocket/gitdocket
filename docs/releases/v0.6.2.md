# GitDocket 0.6.2

GitDocket 0.6.2 makes tracked workflows easier to continue: atomic edits, reusable source versions, compact results and scoped cleanup reduce avoidable reconstruction and retries. It adds guarded worktree targeting and reconciliation, focuses noisy lint, and avoids verified unchanged cache publication. Bounded pickup and context diagnostics keep missing evidence explicit. Website command copying and the latest canonical maintenance changes are included in the same candidate. Named Epic supervision, Board sorting, connected-tool examples and pinned release tools remain available from 0.6.1.

## Agent overview

- `docket overview --json` and MCP `overview` now return the same bounded `agent-overview/v1` briefing with live work, omitted counts, dated authored context and Git highlights. The previous complete JSON model remains available with `docket overview --json --full` or MCP `overview` with `view: full`; callers relying on old default fields must request full explicitly. Human `docket overview` and Home retain their existing presentation. The default JSON has a 16 KiB UTF-8 budget with explicit byte-driven omissions; next-work identity and coordination warnings remain complete. This bounds the response, not metadata or Git computation cost.

## Atomic writes and reusable results

- Multi-field task edits validate the complete patch before one source write. Invalid patches leave source unchanged; successful saves return a reusable source version and unchanged retries avoid another source write.
- CLI writes can opt into `--compact --json`; supported MCP mutations use `response: compact`. Versioned write/error receipts have an 8 KiB UTF-8 budget and report changed/applied/unchanged/unknown outcomes, recovery and source detail routes. Legacy full responses remain available.
- CLI `task create --input <json-file>` and MCP `task_create` with `body` create complete Tasks or Epics without a placeholder read/edit cycle. Initial authored bodies are limited to 64 KiB; ID allocation, exclusive destination protection and validation preserve existing source and lifecycle state.

## Scoped cleanup and worktree coordination

- CLI `task stop <ID> --workflow-token <token> --json` clears only matching checkout lifecycle state while preserving task status. Close results retain lifecycle for the task-linked commit hook and return guarded cleanup arguments; `--after-commit <sha>` requires the unchanged terminal task source and trailer in that reachable commit. Refusals and interrupted cleanup retain explicit recovery evidence.
- MCP writes resolve intended checkout metadata, a deliberate `--repo` pin or unambiguous client roots before mutation. Target mismatch and ambiguity refuse safely. Receipts identify the selected checkout; identified launch fallback remains available when a client cannot supply roots and does not confirm worktree intent.
- Worktree observations use each source's configured Task prefixes. Pickup, relevant Task writes and overview expose body/instruction drift and committed terminal closeout missing from local open state. Foreign completion is advisory and never silently changes local status, readiness or accepted integration.
- Reviewed reconciliation plan/source/apply/recover commands preserve independent authored work, surface same-task semantic decisions and retain journals after interrupted writes. They do not merge application code, automatically choose a winner or infer acceptance from a branch's status.
- Prepared-worker workflows assign task-local evidence to workers and shared epic/log/discovery updates to the integrator. Deferred status never unblocks dependencies. Owner-accepted epic closure concludes eligible children and the epic in one validated commit; standalone closure retains its complete requirements.

## Focused validation and refresh

- Lint diagnostics have stable codes/categories. `lint --summary --json --report <file>` returns a bounded 8 KiB summary and complete source-bound evidence. Optional `--baseline` and repeated `--changed-path` highlight introduced, resolved, pre-existing and unknown findings. All global errors and existing strict warning semantics remain effective.
- CLI `index --json` reports index/cache changes and work. Freshly observed source/configuration/engine/schema/marker/Git inputs plus exact cache bytes can avoid unchanged cache publication. Missing, corrupt or uncertain evidence rebuilds safely; `--rebuild` remains explicit and `--check` is read-only. MCP index still refreshes Markdown discovery without SQLite publication.
- Shipped guidance performs discovery and lint once after the final source/state/log edits in each batch and reuses evidence only while its applicability is known. Workflow instructions are reused through the same pass; canonical close is read when closure begins, and generated native close pointers are retired while customized content remains protected.

## Pickup and context contribution

- CLI `task start <ID> --compact --json` opts into versioned 32 KiB Task/Epic packets. Task identity/source version, dependency blocker totals, guidance, conflicts and authority remain explicit. Omitted required source carries exact detail/continuation routes; full pickup remains the default and source reads never require repeating a mutation.
- `telemetry report --trace <supplied-file>` reviews Docket-specific command/workflow-read patterns in an explicit bounded host export. Add `--context --json` for an 8 KiB contribution/reconstruction review: largest supplied output representations, optional caller-measured response/schema/host observations, source-version evidence and recorded compaction windows.
- Stored telemetry remains opt-in and content-free. Explicit trace analysis does not scrape sessions, persist raw exports, automatically collect shell reads, infer host occupancy from bytes or treat frequent reads as proven waste. Missing/cumulative/estimated/partial host usage stays separate from current-context observations.
- A source fixture replay used 23 versus 24 calls, emitted 49,940 versus 72,136 CLI stdout/MCP envelope bytes and avoided two shared-file conflicts while adding required validation. Schema/instruction material grew; the measurements do not establish general speedup, token savings or improved model reasoning.

## Website and maintenance

- Code blocks and compact command panels provide coherent copy controls; copied inspection steps avoid leaving the user inside Git's pager.
- Public-preview copy, obsolete image cleanup and dependency-update routing are reconciled with the canonical source. The lockfile's fast-uri override is updated, and the bounded high/critical dependency audit remains a required release gate.

## Compatibility and qualification

- Existing full pickup/write/lint/source access remains available. Scripts relying on the former default overview JSON model must request its full view explicitly. MCP lifecycle start/close/stop remains CLI-only.
- Installing updated executables does not update repository-owned instructions. Review `docket upgrade`, preserved customizations and any `reviewRequired` differences in each adopter before relying on current workflow behavior.
- Native artifacts and npm/Homebrew installations have exact-source platform qualification requirements. Cross-compilation, version reporting and local source evidence alone do not prove an installed product.
